# v13b 内推修复验证冻结协议

## 为什么需要新验证

v13 的位置矩阵在正式留出中确认：`kill_first` 和 `kill_frontload` 都会把匪徒放到首个发言位，而当前公共协调基线会集中投首个发言位，因而这两种刀法使首日出匪率达到 100%。v13 条件内推实验预先固定了 `frontload`，所以六种声明的第一目标都必然是匪，无法区分一般的内推覆盖收益。这是设计诊断，不是内推有效的证据；原始结果保留且不删除。

本修复在看到 v13 后登记，不能算原始预注册分析。它使用全新、互不复用的 seed，只改一个因素：匪方首夜从合法非匪目标中随机刀人。验人仍为 `gap`，条件仍是首夜死警且首验好人，六种好人声明和四种第二夜匪方回应完全不变。

## 检验问题

1. 干净单人内推能否把首日出匪率从无内推时的公开锚点基线提高到理论上的约 `4/11`？
2. 三人表是否提高“至少覆盖一匪”的概率，却不自动提高第一归票目标的命中率？
3. 把一名警察放入并明确摘出是否产生可被 `response_removed` 精确利用的位置泄漏？
4. 把真实金水放入并摘出，是否保留相似的白天归票效果而避免泄露警察？

理论校准：在死警、验一名存活好人后，干净候选池含 4 匪7民。随机位置下，1/2/3 人名单至少一匪概率分别为 `4/11`、`34/55`、`26/33`，三人名单的期望匪数为 `12/11`。这些校准只检查候选生成，不预测完整终局胜率。

## 样本与界限

- 训练：每格 1,024 个相同配对条件开局，seed 扫描从 125,000,000 开始。
- 留出：每格 4,096 个相同配对条件开局，seed 扫描从 126,000,000 开始。
- 6×4 矩阵先用训练收益求有限经验受限混合并冻结，再在留出矩阵评价上下界。
- 结果仍受固定投票、声明和夜刀启发式限制；精确矩阵解不等于完整游戏均衡。
