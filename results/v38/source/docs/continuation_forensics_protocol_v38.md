# v38冻结方案：同样首日出匪，为什么续局由胜转负？

日期2026-11-12。只做非干预审计与固定策略新批确认，不修行动，不扩大q，不加信用，不取消查杀对象候选。

## 字典及研究对象

- `original`：v37原接收器，首日活来源冲突先比较来源。
- `retain_hits`：v37候选集扩大分支，将合资格查杀目标加入并按原位置排序投票。不是强制出查杀。
- `late_copy`：普通安全后位刀；死者报金水时可复制，否则继承原假查杀；活来源死亡可触发匪方既有接续跳警。固定团队票。所有实际参数以v37冻结文件为准。
- q50：继承v35的私人条件局部50%回应，非最优比例。数值信用继续冻结。
- `known_false_sources`：仅警察凭自身队友名单发现的跳警非队友；这是警察私有事实，在“平民不假跳、警察诚实报告”的受限策略前提下可判匪，不可直接传给平民。
- `known_bad`：行动者依据私有验人/自卫/警队名单可判定、且该轮可投的匪。
- `call`：当天普通发言的正式accuse归票；`report`为验人声明，`relay`为授权后的更新，不能混为同一条指令。
- `coverage`／采纳：一个明确目标是否进入平民接收器认可的来源建议，以及是否被实际投票。未跟从不自动等于错误。
- 每日子结果：逐夜/日存活(P警,M匪,C民)，另记录公开、私有来源事实与行动。只作过程结果，不设新权重、不改0/1终局收益。

## 范围与预定核查

历史：完整重放late_copy的2048对（4096局），与v37全部完整轨迹哈希、胜负、开局和首日出人匹配。核心事后选中集合为旧胜新负且两边首日出匪的91对，核查其他307对同出匪过程改变和“出警→出民”14对以免只读失败案例。

逐次观察自己的Observation，审计：
1. 警察已有假警或其他已知匪时，合法票是否优先投已知匪；有公共警队正式目标时能否协调。
2. 普通发言时有报告、也知道活匪时，是否真的明确归票。后来才暴露/进入PK才得知应分开。
3. 每个平民能看到哪些当天归票；是否反证来源、受PK或金水保护限制，建议被何条接力替换，是否仍进入建议合并。
4. 同时记录普通发言选择器与实际投票选择器在完全相同信息前缀上对比，只标记分歧，不改变行动。
5. 按所有夜刀（包括终局夜）及日放逐重建人数，避免终局夜未进入发言循环而漏记死亡；与每次实际投票的存活名单交叉核查。

全新确认：213000000–213001023，1024对（2048局），同一late_copy及两接收器。全部核验相同首日投票前公开信息。没有训练/择优步骤。两项预定指标为终局好人胜率差、首日出匪率差；沿用配对二项边际Clopper–Pearson区间＋union bound，两项同时95%。每日人数、行动/信息分类和91场切片只作描述，不作新的显著性主张。

## 解释边界

91对按旧/新终局选中，属于事后机制审计，不代表总体或“选这些场景可获胜”的可实现策略。两边同日出匪也不是随机化的独立干预；不能把后续差异全归结为“留活悍跳者”，更不能据此宣称查杀对象应排除。

“出民保存警察”对比要保持原本会出谁：出警→出民保住一警；出匪→出民损失匪方出局。它们不是相同效应。现有投票排序未固定谁被信任的来源，因此不能充当“信任权重完全不变，只换该来源的查杀/对跳目标”的严格对照。

存活人数比终局更细，但不能任意当成等价收益；同样(P,M,C)可有不同私有验人、暴露、发言顺序与来源历史。暂不训练逐日奖励或声称代理收益最大化会提高终局胜率。
