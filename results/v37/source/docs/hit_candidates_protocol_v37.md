# v37 冻结方案：活来源冲突中保留查杀对象（2026-11-11）

## 参数字典与唯一干预

- `original`：v35原始投票接收器，首日遇到尚存的来源冲突，先从活冲突端点选择。
- `retain_hits`：只在上述首日投票分支，将当前公开查杀对象并入原候选集，使用完全相同的位置排序选择；不认证来源、不强制出查杀。
- 查杀必须是当前日的普通/PK发言，发言者仍活着、仍为原接收器认可的来源且未被该观察者反证；对象必须投票合法、不与私人好人信息冲突，并通过既有金水保护顺序。
- `q=1/2`：首死跳警者不是警队队友时，由首位有资格的警察独立抽一次50%回应；被查杀的自卫等条件继承v35。不是训练所得最优比例。
- `self_copy_early`：自刀假遗言报金水、活匪较早复制金水；`self_copy_team_relay`：自刀给同伴假金水，活匪配合且假金水可接力。
- `late_copy`：普通安全后位刀，活匪复制死者金水（若适用）；`late_old`：同类普通位置刀，保留原有悍跳。完整继承参数序列化于freeze.json。

这是投票接收器候选集消融，不修改公开发言、正式归票、金水接力、第二日起自动公开、信用分、q或匪方策略。首日投票前完整公开前缀必须逐局一致。后续行为可因首日结果变化。PK仍只能在当轮候选中投票；次日起选择器本身不变。没有新增权重或身份概率。

## 预定设计

4个冻结匪方条件×2个接收器×2048个全新共同种子211000000–211002047，共16,384局完整终局。8局/接收器配置合计16局开发冒烟（212000000–212000001），不用于选择规则。没有训练或调参阶段；不扩大q网格、打平衡或寻找有利种子。

主要指标：每个匪方条件的好人终局胜率差、首日出匪率差，共8个预定比较。使用成对增益/损失二项边际Clopper–Pearson区间加union bound，8项同时95%覆盖；区间保守，不能解释为无误差。

次要描述：首日出警、过程改变、候选池扩大、真实/虚假查杀进入候选集及被投票情况。真伪身份仅终局后评价，策略不读取。报告双方相反结果的案例（最多4局），从本批按seed顺序选，不再搜索新seed；案例不能证明总体机制。

每局断言私人反证与PK合法性；原/新逐局开局和首轮投票前公开前缀相同。抽每格首/中/末三局完整重放，原接收器额外与v35 API核查。核查冻结源码/原始结果哈希。冻结后不可用此批改规则，新增疑问留给下一版。

## 研究边界

保留查杀对象是行动空间设计，不是逻辑定理。本模型首夜共同验一人，故首日“A查杀C、D金水E”不能都是真实验人，确实构成冲突；这一判断依赖共同验人的规则，不能无条件推广到不同天或不同游戏。原冲突端点全部保留，不强行缩成A/C；这一收缩需要额外信息前提，另作研究。固定四个对手的策略评估，不是抗新反制验证、矩阵均衡或完整游戏GTO。动态q(I)和金水发言语义继续待办。
