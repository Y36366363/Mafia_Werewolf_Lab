# v22 冻结协议：历史不相容不等于今天必须出谁

## 策略字典与唯一变化

legacy：v20b补首验一致性后的旧路由。live_pair：仅更改冲突出人资格，双方均活着的边才进入冲突目标池。current_day：仅更改建议时效，行动建议只从当日重新提出的改归/查杀/内推产生。both：同时启用这两项。四行均为固定q50信息协议＋私人记忆；数字50指首夜未死警、尚无真警发言、假查杀未中警队时，预定首名警察在自己的轮次50%概率报验回应，其他情况不由本轮优化。

为了单独检验续局，所有修复从第二天开始。四行第一天完整轨迹、首日放逐、第二夜验人和刀人、第二天普通发言在投票前均应逐局完全一致；记录pre_day2_vote_hash强制校验。不是在本轮重新比较首日跳/藏、额外暴露警察或修改首验模型。

规则固定4警4匪8民，死亡不翻身份、前三死亡遗言、按死亡锚点发言、可弃票、一轮PK再平票平安日。gap验人、等权位置模型、二人内推与真实实际验人声明沿旧版。无平民假跳、真警不乱发身份，金水来源先于目标关系保护保留。警队的真实共享验人和各人私人假警记忆不改变。

四列沿用late_near、late_far、decoy_near、decoy_far：safe_late/反旧位置后验的posterior_decoy刀×首个匪假查杀其后第一个/最后一个未发言非匪。匪只知队友，不知警民；各列后续不再重复新增假跳，继续追公开跳警者并用原投票程序。没有让匪方重新学习对本次修复的最强回应，因此任何提升只对该冻结池有效。

## 从信息到动作

- 所有公开历史与矛盾边完整保存，来源死了不会被认证为真/假；存活者没有免死资格。
- live_pair只让活—活冲突进入冲突来源放逐池，死—活边仍在记忆中，但不能单凭这条边把活人推进候选。PK仅一名冲突者合法时与“对方死了所以只剩一人”不同，不越过PK候选规则。
- current_day只改变“今天能直接作为建议的内容”，不是删除旧验人或认定旧话错误。今天重申的活来源建议、今天死警的新遗言都可进入建议池；过去未重申的死者查杀不自动续期。
- current_day在多个历史来源中只保留有当日合法建议的来源用于建议共识；仅剩一项当日建议时可按唯一当前建议协议采用。这是协调策略，不证明来源是真警；历史仍活的对手若不再重申旧建议，可能失去建议权，本轮匪续局固定，因此是重要局限。
- 私有确知活匪仍最高优先，警察不投私有已知好人；公共金水保护不覆盖私人真相。无当日建议时可比较仍活着的双方冲突，否则回到原位置/公开顺序，不伪造额外身份概率。

本轮不增加信用分/怀疑分数。旧信用只冻结作历史对照，主比较四行均不用数值来源门槛。目标位置分仍是旧模型，建议资格来自本轮规则，投票独立按自己观察执行。当前建议可被匪利用，信息协议不等于完整理性推断。

## 验证顺序

先测人工残局：悍跳者死后真来源不因单条旧冲突必出；旧查杀保存但不能独立作为新指令；当日真警遗言可参考；私人假警记忆、已知好人排除和PK合法性保持；存活者仍可因当前活人对跳或其他证据进入候选，不给免死证。再用v21预定真实三类（失利翻转、反向获胜、孤立活来源）保存的Observation复核。人工/旧例只验证实现，不用于收益估计。

## 新种子与统计

evaluation_A：166000000起4096/单元；replication_B：167000000起4096/单元。smoke仅168000000起；此前164m审计与165m测试不复用。4行×4列×两批＝131072局正式终局模拟，无训练或候选选择，两批在读第一批前一并冻结；不根据A改B。

主比较仅both−legacy的四列×两批八项终局胜率差，给八比较Bonferroni正态近似与有界Hoeffding区间；正常近似低胜负改变数时需谨慎，方差零不证明等效。其余单因素/条件因素对比和次日出匪/出警为解释性逐项配对区间。各行共享seed、首夜与首日完整轨迹；首次干预点为第二天投票，后续状态自然分叉。

报告第一天与第二夜一致性、次日出警/出匪、后续白天出警数、最终胜率。机制计数按每局和每票分开：仅剩死—活旧边而强制比较存活者；把无当日重申的旧死者查杀纳入建议路径；投票碰巧命中旧查杀目标另列为共现，不等同于因果引用。后两类票可重叠，不能相加成独立样本。验证不忽略私有已知匪、不投已知好人、不非法投票。

若修复未改善或变差也保留，不追加策略/seed直到好看。既定续局仍很简化，不能从固定池结果推断完整GTO或一般人类胜率；不求新矩阵均衡。
