# v30 冻结方案（2026-11-04）

目的：接回首夜遗言授权的金水接力，检查接力是否重新把名单交集升级成冲突来源的正式共同建议；审计归票者自己的票；用预先指定的小对照检查兼容伪装与授权真实性边界。不训练策略，不求新均衡，不改信用分。

## 策略字典（先于结果）

四行共用 v29 接收器、位置后验、两人内推、q=1/2、day2+既有金水接力、显式警队归票和私人记忆；信用路由及票型学习冻结。q=0/50/100仍可配置，本轮主矩阵固定50；首夜死警条件没有可选回应节点。

- `notice`：遗言真实金水+两人名单+授权；首日没有额外金水末尾发言。语义修正及来源冲突门均开。
- `relay_typed`：同样消息，加首日末尾金水名单内单归；语义修正开、冲突门关。这是接力升级漏洞的消融对照，不作为推荐规则。
- `relay_guard`：同上，冲突门开；冲突来源即使都正式指向同一人，也不因此跳过来源比较。
- `evidence_guard`：冲突门开；金水可依公开自身矛盾/条件性共享首验冲突选择名单外对象。继承v28见证优先级，故它与list比较同时改变选择依据和权限，不能称纯粹名单外权限效应。

8列：`late/decoy`两种既有位置刀各配`old/copy/quiet`，加`false_notice/false_grant`。

- `late`=safe_late；`decoy`=posterior_decoy。杀手真实执行不加新tremble；好人似然里的2%平滑保持原值。
- `old`：首个匪远位假查杀，原人可重申、死亡后队友可裸跳接续，团队票；对应v29 far_claim。
- `copy`：若到首匪普通发言时已看到首死者的金水，复制该结果，再明确归最后一个合法后置非匪（排除金水），避免首验结果冲突。只能知道自己队伍，不知道目标警/民。没有可复制结果时回到old。后续继承旧策略；因为没有首日假查杀记录，原先依赖该记录的重申/接续可能不触发，这是整套回应对照而非只改单词。
- `quiet`：首日匪全部过，不悍跳、不追加首日反驳；之后照既有续局。没有首日假查杀，自然也没有该记录的接续。它是首日不悍跳，不等于全局匪不行动。
- `false_notice/false_grant`：首夜固定首个匪自刀，遗言报一个按公开发言顺序选出的非匪金水，给两个非匪内推；前者无授权，后者有授权。匪不知警/民，因此可能发到警察；金水是警察时现有平民接力不触发。其余匪首日过。两列同Nature、同首验、同首死，仅授权字段不同。授权会同时激活委托接收器，故不是完全单一的权限消融。此为合法假遗言压力测试，不是最优自刀或与普通刀的公平胜率优劣判断。

授权/死亡均不认证身份。接力只替代原来源建议，不增加一个独立支持来源。冲突门不保证抓出兼容谎言。公开归票是意图，查杀是声称事实，名单是备选；它们不是身份概率。

## 固定问题与设计

1. notice→relay_guard：同公开遗言下增加受保护接力有无行动/终局变化？
2. relay_typed→relay_guard：接力正式化后是否必须保留来源冲突检查？
3. relay_guard→evidence_guard：公开见证与名单外选择的组合有无额外作用？
4. 每行每刀old→copy、old→quiet：针对接收器的兼容回应/不悍跳边界；这是预设策略评估，不是最佳回应/ exploitability证书。
5. 每行false_notice→false_grant：虚假授权是否被未获私人反证的平民采纳？它如何改变过程？

主配置448，前三死亡遗言，无翻身份；公开顺序投票、弃票、一次PK后仍平票平安日。首日末尾金水槽是研究新增资源，两条relay行相同资源；notice无此资源，对照估计整套协议效果，非纯算法效应。
