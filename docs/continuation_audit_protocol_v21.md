# v21 只审计续局：冻结策略不修、不调q、不扩池

## 字典与范围

original＝v20信息路由；corrected＝v20b只补首验一致性的路由。都为evidence_q50：来源信用分冻结不用，私人记忆开启，窄条件首警回应概率50%，gap验人、位置排序、二人内推、三死亡遗言、一轮PK再平票平安日。四列late_near/late_far/decoy_near/decoy_far分别为后置刀/伪装刀×近端/远端假查杀，与历史定义相同。

本轮不改任何策略、裁判或数值，不求均衡。主任务是全量重放已有v20b的8单元×2048＝16384局，逐局核对已存胜负与首日指标，记录完整对局的决策来源、信息权限和行动。新种子164000000起，各列512对（共4096局），只检验相同异常机制是否出现，不据此优化策略。旧样本属于事后解释、新样本属于预定审计验证；都不能把票次数当独立局数或断言总体最优。

## 预定检查

1. 好人是否忽略自己已知且在合法候选内的匪/假警；警察是否投自己私有已知好人；合法候选/弃票是否遵守PK。
2. 同一天同一轮警方私有信息相同的活警是否投向同一已知匪，记录分票与PK限制，不能因未知阵营分票自动叫程序bug。
3. 平民是否继续用死亡、过时或已被自身证据否定的来源；来源死了不等于翻身份，不把“历史声明可保留”当作本身错误。单列历史冲突中只剩一个活来源时是否强制投该来源，检查其真实身份（仅评价器事后标注）。
4. 夜刀是否优先命中公开警察，次日验人是否被发布；存在活查杀却只发布最新金水的次数、警队内部和公众信息差。
5. 首日匪/警/民/无人出局分布、次夜刀与次日出局、最终胜负配对迁移。分解同样首日出局但后续不同、首日出匪增加却由赢变输等；条件相关只是定位，不是独立中介因果效应。

## 选例与冻结

每列按种子升序，预先取每类首例：原赢修后输且修后首日出匪；原输修后赢；两者首日相同且输赢不同；修后出现“仅剩一个活冲突来源，平民投真警”。这些例子是为解释而挑选的事后个案，不能代表出现频率，频率从全部重放计数。每例保存双方完整公开轨迹、夜间行动和每次投票时的观察及决策解释；角色真值单独标记为评价层，绝不传入策略。

包装器与原程序相同的观察和随机数输入，只读记录，不改行动。源码使用v20b归档包；审计脚本、参数与协议另存哈希。对每个旧样本核对已保存所有raw指标；另用不带包装器的原冻结API抽样重放，确认包装器不改变轨迹。

## 后续问题保留

警察跳/藏及其局部混合是核心研究问题，待续局与信息权限审计可解释后重新启动。信用分保持冻结对照，将来单独与替代规则比较，不作永久移除。信息集/票型/存活推理/多匪团队对冲另行预定实验；本轮不加入。
