# v30 完整方法与结果：金水接力、来源冲突与兼容回应

2026-11-04。主配置4警4匪8民；本轮为冻结策略与接收机制评估，未训练新策略、未求新均衡，更不是完整GTO。完整旧案例另见[逐日解释](relay_receiver_cases_v30.md)。

## 1. 策略与参数字典（先读这里）

数字v30是实验版本，不是信用值；本轮没有新增信用分或身份概率。q=50表示有回应机会时既有首警50%回应，随机来自独立决策键；不是50%信任。q0/q50/q100仍可配置，主矩阵只跑q50，死警分支本来没有可选回应节点。本轮不重新学习最佳跳藏比例。

| 行名 | 实际动作 | 与对照的差别 |
|---|---|---|
| notice | 死者金水+两人内推+授权；无首日末尾金水单归；语义修正与冲突门均开 | 上轮both对应的接收规则 |
| relay_typed | 加金水末尾从名单选一个正式单归；仅语义修正 | 故意关冲突门，检查正式化是否绕回旧漏洞 |
| relay_guard | 同名单内单归，冲突门开 | 即使两个来源都明确推荐同一人，也先检查来源冲突 |
| evidence_guard | 冲突门开，金水可按公开见证选择名单外对象 | 同时改见证优先级和可选范围，不是纯权限消融 |

所有行保留day2+原有活警委托、本地私人记忆、显式警队归票、两人内推、同一位置后验；不启用数值信用路由或新的票型学习。金水槽是首日普通发言结束后的额外研究资源，notice没有这一槽；其余三行的槽与次数相同。名字中的guard是来源冲突检查，不是身份认证。

| 列名 | 实际匪行为 |
|---|---|
| late_old | safe_late首刀；首个匪远位假查杀；原人重申、死后队友可接续；团队票 |
| decoy_old | 同上，首刀改posterior_decoy位置伪装刀 |
| late_copy / decoy_copy | 到自己普通发言时若已见首死金水，复制同一金水结果，再正式归最远合法非匪（排除金水）；未见则回old |
| late_quiet / decoy_quiet | 首日所有匪过，不悍跳；其余同继承续局 |
| false_notice | 首夜首个匪自刀，遗言给公开顺序第一个非队友金水，再给两个非队友名单；无授权，其余匪首日过 |
| false_grant | 与false_notice同发牌、同首验、同首死、同金水/名单，加遗言授权 |

`copy`只读取已经公开的结果及自己的队友，不知道所选非匪是警还是民。它没有首日假查杀记录，继承的“重申该查杀/接续该查杀”节点可能不触发；quiet亦如此。这是整套可执行回应的比较，不能把差异全归于相容性一个词。false列可能把金水给警察；该警不接平民专属接力。假遗言授权增加公开字段并激活相关接收范围，是压力测试，非最优自刀结论，也不是全游戏中自刀频率的估计。

**四个概念分开：**查杀是声称的事实；内推是备选；归票/relay是行动建议；实际票由私人事实、合法候选及接收规则产生。来源相容不等于真实；被金水不自动得到验人信息；死亡不认证身份。接力替代原来源的建议，不额外复制一个独立支持者。

**数值来源：**两人名单、q=1/2、前三死遗言与2%后验平滑均继承已有研究约定，未经本轮调优。2%在好人的似然模型中防零概率，未向真实匪刀新增2%随机操作。所有新分支都是离散规则，无分数累积、无新增阈值。

## 2. 先把旧502局解释清楚

这部分是**v29旧资料重放/分解**，不是今天新的确认。旧合并13胜、修正52胜：13局原本赢且仍赢，39局输→赢，450局仍输，0局赢→输。314条行动路径改变，恰有39条转赢、275条仍输。39条转赢全部由首日没出匪变成首日出匪。因此终局增量有明确的逐局对应；但没有估计中盘状态价值，不能把多出一匪直接叫“胜率提高多少”。

**例189000018（座位1起）：**首死4号警报15金水，内推3/8；7号匪假查杀3。旧规则先取共同目标3，七名好人随错票，警队和被查杀者投7；修正先处理首验冲突，首日出7。此后旧线第2/3/4日出7匪、1匪、11民，第5夜末警10被刀；新线第2/3/4日出1匪、14匪、13匪，最后一警10尚活而匪全灭。后续验人也改变：第3夜旧验1，新验14。收益经过续局传播，不是单一动作效果。新线1/13接续假警，让真实警队能从自身信息辨伪并明确归票；平民没有直接获得警队私密名单。

**例189000003：**修正把首日错出11民改成出14匪，随后在警队灭亡前多出5号匪，但第4夜末警13仍被刀，15匪尚存，仍输。它确有过程影响，没有终局翻转。完整身份、逐日验人/死亡/归票与底层记录见[案例附录](relay_receiver_cases_v30.md)、`results/v30_examples.json`历史部分。

**归因边界：**v29两项单开与双开都恢复原不追加名单的anchor轨迹和52胜，未超过anchor。主要是避免新增信息被错误合并引入的损失，不是凭空收集新信息；也没有证实对兼容假警/假遗言稳健。

## 3. 本轮方法与样本

32单元=4行×8列。开发每单元64局，191000000–191000063；验收每单元2048局，192000000–192002047。共67,584次正式完整对局，逐局实际执行；共享2112个基础seed，不是67584份独立牌。烟测64局另计。规则/源码/参数在开发运行前冻结，开发后不择优、不改q/列/规则，验收后不追数字。日期或新一批原始胜率变化不能直接叫进步。

前6列主要条件是“首死真警且首验非匪”；这是裁判侧评价分支，不是玩家得到的信息。后2列首死匪且已自刀，评估所有2048局，不能与前6列直接比较推断自刀优劣。每个预设配对同首夜状态；不同刀不强求同首死。角色知识不对称本是游戏规则，信息合法性要求策略只用自己的观察，而非要求警民匪有相同信息。

24个接收器比较+16个匪回应比较+4个假授权比较，共44对×终局/首日出匪两指标=88项。使用配对正负翻转频率的Clopper–Pearson界和union bound，提供家族95%区间；不把经验零差写成总体等价。所有88项完整数值在冻结holdout.json；以下百分点评估均用该同时区间，普通正态区间只作原始兼容字段。配对依Nature与决策键共享，不宣称所有对照都因此降低方差。

**假授权，无接力也受害，seed192000016：**6号匪自刀报7好人，名单8/10；11号真警随后报8好人。无授权时闭眼平民按名单交集出10平民，最终好人仍赢；加授权后，接收器开始优先比较冲突来源，死者6不可再投，转而出存活11真警，最终输。金水没有末尾接力（notice行），其余发言前缀一致，只多授权字段。**这是首日残留的“仅活来源可被投”偏置，被授权触发的范围变化暴露；不能称为合理鉴真。**day2+不机械轮出的修复未撤销，但本轮不再宣称同类问题在首日已彻底排除。此例和假授权总体的负效应，应在再次调跳藏或信用前优先处理；本轮只报告，不修改规则。

## 5. 信息合法性、合理修复和反制不足应怎样区分

- 本轮没有给好人新增秘密角色、未来验人或匪策略名称。复制金水用的是公开结果，假授权不会被裁判自动拒绝。信息权限测试含隐藏警/民交换后同一观察同一动作；这不是对所有信息集的穷举证明。
- 语义修正解决的是把“怀疑C或D”误当“必须出C”。冲突门解决的是将不相容来源因目标重合视为互证。它们属于接收机制的合理修复，不保证所选活来源一定坏。
- 金水最终单归会把软名单变成明确执行目标：若只保留typed，可能再次走进双方正式建议相同的早合并。guard在同一信息下阻止它；兼容的谎言仍可通过，因为相容只说明没有发现矛盾。
- copy与quiet均在开发/验收前确定，无根据验收胜率找seed或训练回应，故本轮不能称为对验收样本的拟合；它们确实针对固定接收器结构，是合理的策略压力测试。其成本是普通发言内容与后续路径变化，未加角色预知。
- 假死者能授权说明程序没有偷偷把死亡当认证；它也暴露强信任真实遗言条件局的外推边界。不能把真死警与匪自刀局任意相加成“最优混合胜率”：需要先规定匪刀法混合、玩家所知及信息集合法性。
- 所有结果仍依赖固定警察验人、低表达复杂度、单警曝光、杀手优先刀公开来源等续局。总体偏匪的低胜率既有规则与续局原因，也可能有未修好的协调策略，不能归为人类比赛的已证事实。

## 7. 下一步建议与分开保留事项

先修订研究问题：如何在不认证死者的条件下处理死/活冲突，且不让授权字段替旁观者决定谁假；同时决定是否统一发言选择器和投票选择器；如做，需固定信息时点、保留私人反证/PK约束，另用新种子确认，不以本批调规则。再讨论兼容谎言的来源处理和票型依据，避免马上堆数值信用。
