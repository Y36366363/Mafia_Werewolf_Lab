# v24：接续反制是否触达原本可赢的路径？

2026-10-29。规则、候选与种子在正式训练前冻结；本报告区分接续机会、局部行动损害和终局胜率。

## 策略／参数字典（先读这部分）

|名称|具体动作与继承关系|
|---|---|
|repair_q0 / repair_q50 / repair_q100|两项续局修复、私人记忆、来源无数值信用的路由不变；仅在规定窄条件下，首位真警以0% / 50% / 100%概率回应假警。数字是行动概率，不是身份或信用。|
|quiet|原固定匪续局，仍刀人、投票和发言，不特意重申旧假查杀。|
|restate|原悍跳活着、旧目标活着：自己在普通发言扩展重申今天出旧目标。|
|support|保留restate；原悍跳死后，首位活匪仅说“今天出旧目标”；普通占位不改，不自行跳警。|
|claim|同support的触发、说话者、目标及accuse扩展；普通占位改成“我跳警”。不报新验人。|
|late / decoy|safe_late位置刀 / posterior_decoy伪装刀；最高分合法刀中随机破同分。不是随机刀。|
|near / far|首日首位匪在自己后续发言的非队友中，选最近 / 最远者假查杀；不知道这个人是警还是民。|
|trained_local_q|仅由训练的两个端点×16匪列选出，留出前冻结。若等于现有行，只引用同一行，不重复计局。|

**q何时生效：** 首夜未死警、预定首警还没发言、已出现假警且查杀未中警队时，只有这一名警在自己的轮次抽一次。q0不是全游戏永远藏，q100不是全警队跳；被打中警队的必答分支不由q控制，也不机械拉第二警。

**数值与权限：** q是人工定义的端点/对照概率，0至1，不积累、不更新；训练选出的有理数q也仅作用于这个单节点。信用分未重新启用。原位置后验的等权假设、2%似然扰动、gap验人和二人内推沿用：2%在好人假定的刀似然中，并未加到实际匪刀。位置怀疑排序、建议来源资格和最终投票是不同模块，不是统一身份概率。

兼容字段source_credit=True仍保留，但实际routing=evidence不调用数值信用投票分支；history=False只关闭旧票型加分，remember=True仍保存跨日私人反证，公开消息也未删除。

所有动作由固定程序及决策键随机数产生，不用LLM实时推理。规则仍为4警4匪8民、警互认并共享夜验、死亡不翻身份、前三死亡有遗言、可弃票、一轮PK后再平票则平安日。本池无平民假跳、真警乱报或自刀策略；这些是当前结论的前提与边界。

## 本轮先回答三个问题

1. **反制现在确实覆盖原本能赢的支路。** 固定q50的四组中，约89%—95%的原获胜局出现接续机会；接续跳警使总体好人胜率下降约3.2—8.6个百分点。四项同时95%的二项补充区间均排除零。
2. **问题集中在当前来源与归票协议。** 队友只建议旧目标时，本次q50留出未见终局翻转；同目标、同归票信号加一句自己跳警后，结果明显改变。仍需具体动作区分平民接收与警方私人识破两条通路。
3. **跳藏暂有端点证据，尚无通用最优比例。** 训练选该窄条件q0，留出该冻结池的最坏列也优于q50、q100；不是完整游戏最优隐藏，更不证明所有局面都应藏。

## 为什么上轮会从“先出匪”变成“先出民”

历史训练例169000044（下文座位从1开始）：14号匪第一天假查杀15号民。第二天不重申时，10号民、14号匪、1号民各4票进入PK；重申后，匪队四票从1号改到15号，PK变成10、14、15。

关键是10号平民的一票：他原先投11号；PK时11不在候选里，自己也不能投自己。真警给的名单10、11对他没有合法候选。不重申时，他按位置回退投14号，匪以5票出局；重申时，程序发现14号今天还有“出15”的有效建议，就改投15号，民以5票出局。

所以这里是**四张匪票改PK候选，再改变一张关键平民票**。没有新证据，也不是全场突然相信旧查杀。两局最终都输，二元终局指标掩盖了局部出人损失。本轮已重新完整重放并与v23两条归档哈希一致。

## 本轮接续究竟增加什么

例如A假查杀C后死亡，C仍活着。B是A的匪队友：support只说“今天出C”；claim先说“我是警察”，再给同一个建议。两者都使用accuse，匪队均能协调投C；claim额外改变B在当前路由中的来源资格，也让真警凭互认私下识破B。不是给B增加夜验，不是将A的谎言变成B的独立检查。

接续只在当前发言序首名存活匪的普通轮次执行，一条普通声明加一条扩展；旧目标死后不换人，不追加PK发言，不刷新死者消息日期。依据只有自己的匪队、公开旧消息、死亡与发言序。未知警民标签仅用于事后评价。

当前接收协议只将report/police声明者纳入来源；纯投票建议不自动获得来源资格。新的police+accuse未必产生基于report矛盾的冲突边。这是受测协议边界，不能把来源资格当认证真警。
